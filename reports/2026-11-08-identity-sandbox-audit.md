# macOS 身份来源隔离与官方 Claude Code 实测

日期：2026-11-08。实机：Intel macOS 15.8.2。Windows 实现已移除；Apple Silicon 仅完成交叉构建。

当前实现已从单一 JS 适配扩展为“系统来源限制 + 原生身份提供层 + Bun 启动适配”。普通项目文件保持真实路径和原生接口；只有用户明确允许的系统身份来源受到选择性限制。已完成下表中的有限验收，尚不能宣称所有宿主信号均不可识别。

## 测试对象和方法

使用 npm 官方 darwin-x64 包中的原始 Claude Code 可执行文件，未修改其磁盘内容或签名：

| 版本 | 内嵌 Bun | SHA-256 |
| --- | --- | --- |
| 2.1.169 | 1.3.14 | `6d8d510c715b899307b7d29a1062d43e62c99370c55330dac3ec1851a2fbf7c8` |
| 2.1.319 | 1.4.4 | `af6f1f5510ae98d56a155bf8f007aa9d5b44efccc9c10c8e10ef35039e95a940` |

两个文件均通过严格签名检查。当前默认 PATH 未发现已安装的 `claude`，实测明确指定上述官方文件，没有将替身程序当作 Claude。

实际客户端解析参数、初始化、构造并发送 HTTPS 请求；受控本地 TLS 服务记录请求并返回固定模型响应。测试使用无效 dummy 密钥、独立临时 HOME/客户端状态/工作目录和仅对子进程生效的测试 CA。唯一转发到公网的测试流量是经现有本地代理进行的美国出口预检。没有使用真实账户、订阅或远程模型；这也不构成真实 OAuth/系统浏览器登录验收。

源测试位于 `tests/real_claude/` 与 `native/*/test*`；可复查摘要、资产哈希和单项结果见 [机器可读证据](evidence/2026-11-08-summary.json)。

## 隐藏日期标记

已找到原始 [Claude Code issue #67120](https://github.com/anthropics/claude-code/issues/67120)。该报告讨论端点和时区引起的系统提示日期行变化，没有证明服务端如何使用这些字节，也没有证明开发者意图。

我们另用实际 macOS 2.1.169 动态复现：不同自定义端点分类产生 `U+0027`、`U+2019`、`U+02BC`、`U+02B9` 四种外观相近字符；中国时区触发日期分隔符 `/`，美国 Profile 时区为 `-`。端点分类与时区是不同输入，美国时区不能隐藏用户显式选择的自定义端点。默认官方端点在已测条件中未触发同样变化。2.1.319 的已测矩阵没有复现这些变化，不能推断其所有条件分支均不存在。完整前期证据保留在 `2026-11-07-real-claude-audit.md`。

本产品没有通过改写请求正文掩盖该行，而是控制客户端读取的身份来源、默认 API 路由和独立客户端状态。

这些计数分别描述场景、断言、写入槽和属性种类，不能相加为“总信号覆盖率”。

文件性能另测 5 个交替轮次，每模式每轮 10 万次缓存文件 `open/fstat/read64/close`，目标内部计时不含启动/出口探测。裸进程为 13.169 µs/次，完整策略 13.457 µs（+2.18%），完整策略加原生提供层 13.597 µs（+3.25%）；15 个完整样本、冻结组件及源码均保留。所有文件函数仍来自系统内核库，内容/inode/所有者保持。该测量有调度、电源和缓存噪声，不能宣称零损耗或外推真实 Claude 全部工作负载。

工具子进程中，8 个代理变量与原生 C `getenv` 一致，私有启动变量均已清理。`USER`、`LOGNAME` 等必要值符合 Profile；`USERNAME` 别名不可用。原生账号与主机名查询受限返回不可用，没有将这种拒绝写成“都已返回 Profile”。

早期工具测试用字符串前缀检查代理 URL，误拒绝了带随机会话认证的合法回环地址。已修正为 URL 解析与逐项 C 环境检查，保留早期失败记录；不能据此宣称旧实现一定缺少代理变量。环境发布现在由原生清理接口明确同步，Bun 与 C 两份环境均有实际断言。

## 系统来源保护

仅拦截高层电脑名 API 不足以隐藏真实电脑名：Apple 的公开实现存在系统偏好回退，实测也观察到该回退。当前规则同时限制对应服务、偏好域和具体来源文件。[Apple configd 实现](https://raw.githubusercontent.com/apple-oss-distributions/configd/main/SystemConfiguration.fproj/SCDHostName.c)

精确限制包括系统电脑名、接口/Wi-Fi/共享名配置、自动时区/位置偏好、全局语言区域、用户文本编码、时区/解析器别名及登录记录。ByHost 文件名包含机器 UUID，故额外限制该目录枚举，但已知非身份子文件仍可直接打开。

身份来源读写均受内核规则限制，普通文件没有用户态 I/O 包装。所有写保护测试仅作用于临时副本，未尝试写真实系统身份配置。

边界测试最初发现 Preferences/ByHost 若指向普通项目，canonical 路径可能误伤项目。已修复为：身份目录或叶子重定向时拒绝该次启动；顶层 HOME 别名仍支持。最终 15 项通过，初始失败记录保留。

## 原生提供层与长期兼容

官方客户端的 Bun 入口同步加载原生库并修改身份 API 的导入数据指针，不修改系统代码入口或官方磁盘文件。生产实现跳过自身映像，不 Hook `dlsym`，不接管普通文件 API。每次写槽均验证数据页原 current/max 权限已经恢复，加载后的新映像在其 constructor 前处理。Profile 配置、账号快照和 CF 对象缓存于进程内，临时环境清理后仍可工作。

初始化要求自检 `255`、ABI/结构长度匹配、主映像实际匹配并成功写槽、各类失败计数为零，再发送最终就绪确认。单纯“加载成功”不被视为激活成功。故障注入接口只存在于单独测试库，未进入分发库。

这种结构没有固定版本字符串依赖，但仍依赖客户端保留可用 Bun 入口、FFI/库加载权限和受支持的二进制导入布局。新增或改变信号需要重新审计。

## 明确未完成的保证

- **任意原生入口与缓存**：保存的直接函数指针、新 `dlsym` 结果和直接系统调用可以绕开导入重绑定；目前由已验证的真实来源拒绝防守。未知来源、应用自带缓存或外部受信进程的协作仍未获得全量证明。
- **新 Bun 环境别名**：1.3.14 原始环境对象锁定已通过；1.4.4 不支持该锁定，保留受控 `process.env` 代理并明确输出部分覆盖。独立检查返回 UNSUPPORTED，没有计为通过。
- **文件透明性**：真实 HOME/项目路径、内容、Git 身份、UID/所有者和其他原生文件元数据保持真实。它们可能关联用户，不能同时宣称原样保留与完全匿名。
- **账号隔离**：独立设备标识不能隐藏同一个服务账号，真实 OAuth/钥匙串隔离尚未验收。删除 Profile 保留登录与历史；新建/复制禁止复用已有保留状态的名称。相同 Profile 不应并发覆盖冲突的 `device_id`。
- **出口证明**：启动与每 30 秒探测只证明该次 HTTPS 探测的出口；代理/VPN 按目的地分流或间隔内换出口仍有观测空窗。中继绑定代理节点或隧道，不等于取得所有远端服务器观察到的源地址证明。
- **系统边界与功能**：本机允许端口上的其他监听者、未知委托服务、主动逃离进程组等仍是边界；本地监听、Unix 套接字与系统浏览器登录可能受限。配置修改在新启动时生效，不会改写已运行会话。
- **平台与性能**：仅 Intel macOS 15.8.2 实机；Apple Silicon/其他版本、arm64e 认证槽未完成实机验收。普通文件接口保持原生，并不能由此推导数值上绝对零性能损耗。

因此本阶段交付的是具有明确测试范围的 macOS 身份隔离实现和可复查证据，不能标成“全部信号、任意未来版本、所有真实登录流程均已保证”。
