# 身份隔离沙箱：需求与系统边界

该产品的目标是让 Claude Code 的系统身份观察保持为一套 Profile，同时保留宿主文件系统和正常开发能力。它不是通过替换某个日期字符串来解决特定版本的问题。

## 行为约定

| 对象 | 目标行为 |
| --- | --- |
| 系统身份 | 用户名、主机名、时区、语言、区域、设备标识由 Profile 提供，彼此一致 |
| 位置与网络身份 | 由沙箱统一选择出口、解析 DNS、限制直连；无法确认出口时拒绝会话 |
| 无法安全提供的受控查询 | 返回不可用或拒绝，不能自动退回真实宿主值 |
| 项目和普通文件 | 保留真实路径、内容、元数据、权限和原生文件 API |
| 系统身份来源 | 用户已明确允许仅对系统电脑名、区域、时区等身份来源进行局部虚拟化；不将这一例外扩展到普通项目或文档 |
| Claude 自身状态 | 使用用户已经允许的独立 `CLAUDE_CONFIG_DIR`，每个 Profile 单独初始化 |
| 其他能力 | 尽量保留；若某个混合 API 同时涉及身份和普通能力，需要明确记录兼容代价 |

“真实文件完全透明”也意味着文件中的姓名、Git 配置、用户名路径、机器标识或凭据仍可能被读到。当前需求应将这些视为文件透明性的边界，不能同时承诺把它们全部隐藏。真实 UID 与文件所有者信息同样不能在保持所有文件元数据原样的情况下全部变成另一身份。

## 分层结构

1. **Profile 与身份状态**：配置、校验、独立设备标识、独立客户端状态和环境值统一来自同一份 Profile。临时命令行覆盖只影响当前启动。
2. **系统访问策略**：内核负责限制能够暴露宿主身份或提供旁路网络的访问。策略不接管文件读写。每一项拒绝规则都要经过实际客户端和普通开发工具验证。
3. **身份提供层**：对可以可靠接管的查询返回 Profile 值。允许注入的程序使用 DYLD 入口；官方签名客户端通过 Bun 入口晚加载同一个原生提供层，重绑定身份 API 导入，并补充 JS 兼容和环境保护。Bun 只是启动适配器，整个边界还依赖真实来源限制。
4. **网络控制层**：本会话中继、随机凭据、代理或 VPN 绑定、DNS 控制和持续健康检查。目标及普通子进程受同一内核网络策略约束。
5. **会话管理**：初始化确认、进程组与终端管理、失效后的连接关闭及后代清理。
6. **观察与兼容性验证**：用官方客户端真实请求对照多个 Profile、时区、地址和版本；同时检查被允许的功能与应拒绝的访问。新版本不以“能够启动”作为隐私验收条件。

## macOS 上已经验证的事实

- Seatbelt 能限制网络，并拒绝部分系统查询。Bun 模式默认启用接口、原生身份、账号记录和身份来源文件限制。主机名、登录名、主机/启动 UUID、已核对的位置/Wi-Fi 服务以及指定 IOKit/NVRAM 身份属性受限。实际 IOService 枚举的 27 种已存在身份属性均被移除，普通平台型号保留。
- 原始 C `uname()` 包含主机名，受限后整个查询会失败。原生身份层现在分别读取其他 OS 字段，避免为了提供系统类型而读取被禁止的宿主名；该层的完整夹具已在身份策略下通过。普通工具 `uname -s/-m` 仍可用。
- 系统沙箱以允许／拒绝操作为主，不能直接给 `gethostname` 等调用返回另一台机器的值。虚拟身份返回值仍需另一层提供。
- 官方 macOS Claude Code 的签名策略阻止通用 DYLD 环境注入；其 Bun 入口已在生产接入原生库晚加载与身份导入重绑定。两版实际客户端各观察到 33 次成功写槽，其中主映像 6 次；数据页 current/max 权限恢复，失败计数为零。已有与后来加载的动态库均有实际调用测试。初始化会要求自检、主映像真实写槽和权限验证，而非只确认库被加载。
- 原生直接函数指针仍可绕开导入重绑定；来源限制须独立存在。生产方案不 Hook `dlsym`、不修改系统代码入口或官方磁盘文件。所有原生来源覆盖仍须逐项检查。
- SystemConfiguration 会读取文件回退。指定电脑名、区域/语言、接口/Wi-Fi/共享名、自动时区、解析器与登录记录文件已限制读写，ByHost 目录枚举受限；已知非身份子文件保持可直接读取。15 项边界检查包括特殊字符 HOME、顶层 HOME 别名，以及身份目录/叶子重定向到普通项目时拒绝启动。首次暴露的目录符号链接误伤已修复并保留失败记录。
- Bun 的不同版本对环境对象的实现不同；2.1.319 内嵌的 1.4.4 存在无法通过替换 `process.env` 同步接管的其他入口。系统级边界不能由单个 JS Hook 代替。
- 实际官方 Read → Write → Bash 工具链已通过两版测试。项目路径、文件内容、inode 与所有者保持真实，普通子进程继承环境与内核规则。子进程的部分原生查询不可用，不能声称它们都返回 Profile。

当前实现及证据见 [系统来源与真实工具审计](../reports/2026-11-08-identity-sandbox-audit.md)；隐藏 Unicode 行为见 [前一阶段报告](../reports/2026-11-07-real-claude-audit.md)。系统身份仍有直接入口、缓存和未知来源等覆盖边界。

2026-11-08 用户进一步允许仅虚拟化系统身份来源。实现依此限制已验证的具体来源，不把权限扩展到整个 HOME 或项目文件。偏好目录被重定向到普通项目时拒绝本次启动，避免为了身份隔离破坏普通文件透明性。

## 信号清单

| 类别 | 提供或限制 | 已知边界 |
| --- | --- | --- |
| 主机/用户名 | Profile 环境、原生身份导入、JS os 兼容；真实系统查询和账号数据库受限 | 子进程未自动注入全部原生提供层；真实 HOME/UID 保留 |
| 时区/区域/语言 | Profile TZ/locale、CF/NS 默认值、清除 TZFILE/TZDIR/CF 及远程登录线索；偏好/时区别名受限 | 普通文件内容、应用自带缓存与新 API 未自动覆盖 |
| 设备与硬件 | 独立 Claude device_id；已列举的 IOKit/NVRAM 属性不可用 | 不是整台硬件虚拟化，未知来源与普通型号仍可观察 |
| 网络与位置 | 会话中继、强制套接字限制、代理或绑定 VPN/DoH、位置服务与指定网络身份文件受限 | 目的地选路、30 秒观测间隔、外部受信进程代发有独立边界 |
| 客户端状态 | 每个 Profile 独立官方配置；新建/复制禁止复用遗留客户端状态的名称 | 同账号仍关联；同一 Profile 不能并发使用相互冲突的 device_id |
| 文件和开发能力 | 项目/普通文件原生；实际 Read/Write/Bash、终端与子进程验证 | 路径/内容/元数据中的真实身份保留；本地监听与部分代理外工作流受网络策略限制 |
| 环境变更 | 受控 process.env 修改拒绝；运行时支持时锁定原始别名 | Bun 1.4.4 原始别名锁定不支持，明确报告部分覆盖 |
| 生命周期/版本 | 初始化与失败关闭、实际客户端审计；无固定版本字符串依赖 | 不能承诺任意未来签名/运行时兼容；Apple Silicon 未实机验证 |

## 后续实现与验收方向

- 维护系统信号清单：每一项记录来源、关联 API、Profile 字段、提供／拒绝策略、子进程行为、实际验证证据和未覆盖路径。
- 优先在系统访问层阻止真实来源，再由身份层提供一致值。不能只证明一个高层 API 已被替换，却忽略同一信号的其他来源。
- 为正常开发能力设立回归检查，包含原生文件、终端、Git、常见解释器、子进程和必要本地服务；拒绝行为的兼容代价必须可见。
- 未验证的信号和版本明确标为未覆盖；不能用“初始化成功”推断完整保护。
- 若验收要求包括所有原生查询、所有文件中的身份信息、任意未来实现，同时维持现有全部硬约束，需要先解决约束冲突。当前平台能力和测试不足以证明存在符合这一绝对要求的实现。
